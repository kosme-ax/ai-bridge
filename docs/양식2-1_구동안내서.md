## 2. 설치·실행 절차

### A. 클라우드(권장 · 심사 즉시 구동)

1. 브라우저에서 `https://sme-ai-helper.streamlit.app` 접속  
2. 메뉴 바로 아래 **AI 상담** expander로 기초체력·과업·견적·정책을 대화 질의 (선택)  
3. 메뉴 **기초체력** → 8문항 체크 → **결과 보기** (교육·정책 추천 확인)  
4. **과업지시서 / 견적 비교 / 정책연계** 또는 **더보기 → CSV 검증**  
5. 사이드바(≡)에서 시연 기업·모델 확인 (키 없으면 Mock)

### B. 로컬 실행

```bash
git clone https://gitlab.aigov.go.kr/kosme2512042/sme_ai_helper.git
cd sme_ai_helper
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # 없으면 .streamlit/secrets.toml.example 참고
# .env 에 SOLAR_API_KEY / GEMINI_API_KEY 입력(선택)
streamlit run app.py
# 또는: streamlit run streamlit_app.py
```

브라우저에서 `http://localhost:8501` 접속.

### C. Docker(선택)

```bash
docker build -t ai-bridge .
docker run --rm -p 8501:8501 --env-file .env ai-bridge
```

## 3. LLM 연결 설정

### 사용 모델

| UI 이름 | Provider | 기본 모델 ID | 교체 |
|---------|-----------|--------------|------|
| Solar | Upstage | `solar-pro4` | 가능 |
| Gemini | Google | `gemini-2.0-flash` | 가능 |

설정 위치: `src/config.py`의 `MODELS` 딕셔너리.  
런타임 오버라이드: 환경변수 / Streamlit secrets.  
관련 모듈: `src/fitness.py`(자가진단), `src/csv_validate.py`(CSV 검증) — LLM 키 불필요.

### 키 입력 위치

**로컬 `.env` (또는 `.streamlit/secrets.toml`):**

```
SOLAR_API_KEY=...
SOLAR_BASE_URL=https://api.upstage.ai/v1
SOLAR_MODEL_ID=solar-pro4

GEMINI_API_KEY=...
GEMINI_BASE_URL=https://generativelanguage.googleapis.com/v1beta
GEMINI_MODEL_ID=gemini-2.0-flash

DEFAULT_MODEL=Solar
```

**Streamlit Cloud:** App → Settings → Secrets 에 동일 키 등록.

### 교체 방법(이식성)

1. `MODELS`에 새 항목 추가하거나 `*_MODEL_ID` / `*_BASE_URL` 변경  
2. OpenAI 호환 API면 Solar 슬롯의 base_url·model만 바꿔도 동작  
3. 사이드바에서 모델 선택 → 「더보기 → 모델 비교」로 A/B 시연

키가 없으면 해당 모델은 **Mock**으로 응답해 기능 흐름을 유지합니다.

## 5. 기능 사용 순서 (핵심 흐름)

### 흐름 1 — 기초체력 → 교육 넛지 (고도화)

1. 메뉴 **기초체력**  
2. 8문항 응답 → **결과 보기**  
3. 등급(준비됨/보완 필요/기초 다지기) 확인  
4. 보완·기초 등급이면 연수원·K-Doctor 링크 버튼 노출  
5. **과업지시서로** 또는 **CSV 검증으로** 이동

### 흐름 2 — 과업지시서 (핵심①)

1. 메뉴 **과업지시서** (기초체력·K-Doctor 요약 카드 확인)  
2. **과업지시서 만들기**  
3. PDF/DOCX 다운로드  
4. 하단에 **중진공 정책 연계 추천**(기술자금·지역 AI 대전환 등) 확인

### 흐름 3 — 견적 비교 + CSV 컬럼 검사 (핵심②)

1. 메뉴 **견적 비교**  
2. 샘플 ON 또는 CSV 업로드(업로드 시 표준 컬럼 검사 메시지 확인)  
3. **비교하기** → 결과 다운로드 → 자금·스마트화 관련 정책 추천

### 흐름 4 — 정책연계 탭

1. 메뉴 **정책연계**  
2. 맞춤 추천 3건 + 전체 카탈로그(개요·일정·신청·담당·문의·링크)

### (선택) CSV 기업현황 검증

1. **더보기 → CSV 검증**  
2. 샘플 또는 파일 업로드 → **검사하기**  
3. 통과 시 **과업지시서 작성으로**

> 진단은 K-Doctor, 접수 서식은 기시행 영역. AI-Bridge는 **기초체력·CSV 검증·과업지시서·견적비교** 실행 레이어입니다.

## 6. 알려진 제약 사항

- K-Doctor **실 API 연동 전** — 합성 진단·합성 CSV로 시연.  
- Data Fitness·CSV 검증은 **제도(공고) 대체**가 아니라 도구 레이어입니다.  
- Streamlit Cloud 콜드스타트 시 최초 로딩이 수 초~수십 초일 수 있습니다.  
- API 키 없으면 LLM은 Mock (기초체력·CSV 검증은 키 없이 동작).  
- 견적 비교·과업지시서는 **참고 초안**이며 최종 행정 판단을 대체하지 않습니다.  
- GitLab Pages는 Streamlit 실행에 부적합.  
- 의존성: `streamlit`, `httpx`, `pandas`, `pydantic` 등 (MIT/BSD 위주). 상용 LLM은 각사 약관 준수.  
- API 키를 저장소에 넣지 마십시오.

## 7. 개발 경위 요약 (1쪽 이내)

### 문제 인식

국민제안은 HWP/PDF 중심 접수·AX 오해·데이터계획 부재·수기 행정 낭비를 지적했고, 전략실은 접수·서식 측면에서 **기시행**으로 답했습니다. 그러나 진단·접수 **이후** AX 지원 현장의 **과업지시서·견적비교**는 여전히 수작업입니다. 또한 제안의 자가진단·CSV·교육 연계를 **앱에서 바로 실행**할 실행 레이어가 비어 있었습니다.

### 접근 방식

1. **역할 분리:** 진단=K-Doctor / 서식=기시행 / 실행문서·검증=AI-Bridge  
2. **핵심:** 과업지시서 · 견적 비교  
3. **1단계 고도화:** Data Fitness 8문항 · 표준 CSV·파일명 검증 · 교육 링크 넛지  
4. **UI:** 토스형 단기능 화면 (기초체력 | 과업지시서 | 견적 비교 | 더보기)  
5. **이식성·보안:** LLM 2종 교체, 합성 데이터, secrets 분리, GitLab 보안 스캔

### 기대 효과

기시행으로 쌓이기 시작한 정형 데이터·진단 결과를, 지원 실행 문서와 기초체력·CSV 품질 게이트로 이어 행정 속도와 AX 인식(넛지)을 동시에 개선합니다.
